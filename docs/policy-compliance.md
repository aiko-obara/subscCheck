# Google Play ポリシー適合

**このドキュメントが、本プロジェクトで最大のリスクを扱う。**

技術的な難所は正規表現だが、**プロジェクトが死ぬとしたらストア審査**である。
通知アクセス権限を要求するアプリは、Google Play で最も厳しく見られるカテゴリの1つ。

## 1. 通知アクセス（`BIND_NOTIFICATION_LISTENER_SERVICE`）

### ポリシーの要点

Google Play は、通知アクセスの利用を「アプリのコア機能に必要な場合」に限定している。
加えて、通知内容の目的外利用・外部送信・第三者提供を禁じている。

### SubGuard の立ち位置

| 要件 | SubGuard の対応 |
|---|---|
| コア機能として必要か | **必要**。無料体験の終了日を自動検知することがアプリの中核。手動登録だけでは商品として成立しない |
| 目的外利用をしないか | 決済・ストアアプリの通知のみを対象とし、パッケージ許可リストで足切りする |
| 外部送信をしないか | **一切送信しない**。サーバーが存在しない |
| 保存範囲は最小か | 通知本文は保存しない。抽出した日付・金額・サービス名のみ |

### Console での申告

Play Console に「通知アクセスを使う理由」の宣言フォームがある。ここに書く内容:

- 対象は決済・アプリストアの通知に限定していること（許可リスト方式）
- メッセージング・SNS・メールの通知は読まないこと
- 抽出するのはサービス名・金額・日付のみで、本文は保存も送信もしないこと
- データはすべて端末内の暗号化データベースに留まること

**この申告と実装が食い違っていると、後から発覚した時点でアプリが削除される。**
実装を変えたら申告も更新する。

### 実装側で守るべき不変条件

コードレビューのチェックリストとして使う。

1. `listener_packages` に含まれないパッケージの通知テキストに、一切触れない
2. 通知本文を DB / SharedPreferences / ファイルに書かない
3. 通知本文を `Log.*` に出さない（**デバッグビルドでも**）
4. 通知本文をネットワークに送らない
5. クラッシュレポートSDKを入れる場合、通知本文がスタックトレースやカスタムキーに乗らないことを確認する

3 と 5 は意図せず破りやすい。デバッグ中に足した `Log.d(TAG, text)` が
そのままリリースに乗るのが典型的な事故。

## 2. 「解約代行」と誤認させないこと

Google Play は、他社サービスの操作を自動化するアプリに厳しい。
また、アクセシビリティサービスを使った自動操作は明確に制限されている。

**SubGuard は解約を自動化しない。** できるのは以下だけ。

- 期限を記録し、通知する
- 公式の解約ページを開く

### 文言のガイドライン

| 使ってよい | 使ってはいけない |
|---|---|
| 解約を忘れないようにする | 解約します / 自動で解約 |
| 解約ページを開く | 解約を代行する |
| リマインダー / 通知 | ワンタップ解約（誤認を招く） |
| 解約ページへのご案内 | 解約手続きの自動化 |

**「ワンタップで解約」は使わない。** 事実として1タップで解約は完了しないし、
自動化を示唆する表現はポリシー上のリスクになる。
正しくは「ワンタップで解約ページへ」。

### 実装での担保

詳細画面の主ボタンの下に、必ず一文を置く（3言語）。

> 「Netflix の公式サイトが開きます。解約手続きはご自身で行ってください。」

これは法務的な免責であると同時に、ユーザーの期待値を正しく設定する UX でもある。
「押したら解約されると思った」という誤解は、低評価レビューの原因になる。

### アクセシビリティサービスは使わない

解約ページの操作を自動化したくなるが、**絶対に手を出さない**。
アクセシビリティサービスの目的外利用は Play で明確に禁止されており、
発覚した時点でアプリが削除される。

## 3. データ安全性フォーム

Play Console のデータ安全性セクションは、**サーバーレス設計が最も強く効く場所**。

| 項目 | 回答 |
|---|---|
| データを収集するか | **いいえ** |
| データを共有するか | **いいえ** |
| データは転送時に暗号化されるか | 該当なし（送信するデータがない） |
| ユーザーはデータの削除を要求できるか | アプリのアンインストールで完全に消える |
| データは端末外に出るか | **出ない** |

唯一の外部通信は `data/cancel_urls.json` の **GET のみ**。
認証なし、識別子なし、送信ボディなし。これは「データ収集」に当たらない。

**この回答を維持するために、広告SDK・アナリティクスSDK・クラッシュレポートSDKを入れない。**
どれか1つでも入れた瞬間に「データを収集する」になり、
本アプリ最大の訴求（プライバシー）が弱まる。

クラッシュ情報が欲しくなったら、Play Console の
Android Vitals（OS が提供する匿名クラッシュ統計）で足りるか先に検討する。

## 4. 課金

| 論点 | 対応 |
|---|---|
| デジタルコンテンツ | Play Billing を使用。他の決済手段への導線を置かない |
| 定期購入との区別 | 非消費型 INAPP。SUBS は使わない |
| 価格表示 | `ProductDetails.formattedPrice` を使用 |
| 誤解を招く価格表示 | 「買い切り・月額なし」を明示 |

## 5. 権限の一覧と正当化

manifest に書く権限は最小限にする。**「あると便利」で足さない。**

| 権限 | 用途 | 必須か |
|---|---|---|
| `BIND_NOTIFICATION_LISTENER_SERVICE` | 通知検知 | コア機能（ユーザーは拒否可能） |
| `POST_NOTIFICATIONS` | リマインダー通知 | コア機能 |
| `INTERNET` | 解約URLカタログの取得 | 必須 |
| `RECEIVE_BOOT_COMPLETED` | WorkManager が内部で使用 | 依存ライブラリ由来 |

### 使わない権限

| 権限 | 使わない理由 |
|---|---|
| `SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM` | Play の制限対象。24h/3h 前の通知に精度は不要（→ [reminder-and-navigation.md](reminder-and-navigation.md)） |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | Play の制限対象。設定画面への誘導で代替する（→ [oem-battery-optimization.md](oem-battery-optimization.md)） |
| `QUERY_ALL_PACKAGES` | 制限対象。インストール済みアプリの列挙は不要 |
| アクセシビリティサービス | 目的外利用の禁止対象。使わない |
| 連絡先 / 位置情報 / ストレージ | 用途がない |

`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` は「リマインダーアプリだから正当」と
主張したくなるが、Play が認める用途は限定的で、審査で弾かれるリスクがある。
まずは設定画面への誘導だけで実装し、実運用で通知の取りこぼしが問題になってから再検討する。

## 6. プライバシーポリシー

ストア掲載にはプライバシーポリシーの URL が必須。GitHub Pages で十分。
3言語で用意する。

記載すべき項目:

- **収集するデータ: なし**
- 通知アクセスで読み取る内容と、その保存範囲（本文を保存しないこと）
- 対象とする通知の範囲（決済・ストアアプリのみ、メッセージは読まない）
- データの保存場所（端末内の暗号化データベースのみ）
- 第三者への提供: なし
- 外部通信: 解約URLカタログの取得のみ（読み取り専用・匿名）
- データの削除方法: アプリのアンインストール
- 問い合わせ先

- [ ] アプリ内・ストア掲載文に「自動で解約」を示唆する表現がないことを3言語で確認した
- [ ] 詳細画面の免責文が3言語で表示されることを確認した
- [ ] データ安全性フォームの回答が実装と一致している
- [ ] manifest の権限が上記の表と一致している（依存ライブラリが足した権限も含めて確認）
- [ ] プライバシーポリシーを3言語で公開し、URL をストアに登録した
- [ ] `verified: false` のままの解約URLが残っていない（→ [cancel-url-database.md](cancel-url-database.md)）

**manifest の権限は必ずマージ後の結果を見る。** 依存ライブラリが
manifest merger 経由で権限を足していることがある。
`./gradlew :app:processReleaseManifest` の出力を確認する。
