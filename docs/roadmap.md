## 見積もりについての注意

当初計画は全体で6週間（各フェーズ 2/2/1/1 週）だった。
設計を詰めた結果、**Phase 1 と Phase 4 は過小見積もり**と判断する。

| フェーズ | 当初 | 修正見積もり | 差の理由 |
|---|---|---|---|
| Phase 0: 基盤 | （なし） | 3日 | プロジェクト生成とバージョン検証が未実施のため独立させた |
| Phase 1: コア | 2週間 | **3週間** | 正規表現コーパスの収集は「通知が実際に届くのを待つ」作業で、時間で圧縮できない |
| Phase 2: UI/UX | 2週間 | 2週間 | 妥当 |
| Phase 3: 課金・通知 | 1週間 | 1.5週間 | Play Billing のテストにストア側の設定と反映待ちが挟まる |
| Phase 4: テスト・リリース | 1週間 | **2週間** | 解約URL全件の人手検証 + 3言語ストアリスティング + 実機テスト |

**合計 約9週間。**

最大の不確実性は **Phase 1 の通知コーパス収集**。
各サービスの無料トライアル開始通知は、実際に契約しないと発生しない。
複数のサービスに登録し、通知が届くのを待ち、キャプチャする作業が必要になる。
ここは並行して早期に着手すべきで、Phase 0 の段階から始めておく。

### 課金テストの注意

- Play Console に商品を登録し、**内部テストトラックにアップロードしないと購入テストができない**。
  ここでストア側の反映待ち（数時間）が発生するので、早めに着手する。
- ライセンステスターを設定すると実際の課金なしでテストできる。
- **返金シナリオもテストする**（Play Console から返金 → アプリでロックが戻ることを確認）。

## Phase 4: 検証とリリース（2週間）

| # | タスク | DoD |
|---|---|---|
| 4-1 | **解約URL全件検証** | `data/cancel_urls.json` の全エントリを人手で開き、`verified: true` にする |
| 4-2 | `manual_steps` の検証 | 各アプリの実際のメニュー名と一致していることを確認（特に中華圏） |
| 4-3 | 通知パターンの実機検証 | 3言語 × 主要決済アプリで実際に検知されることを確認 |
| 4-4 | OEM 実機テスト | Xiaomi / Huawei / OPPO / Samsung の実機で、**数日放置後に通知が届くか**を確認 |
| 4-5 | 権限の最終確認 | マージ後の manifest を確認。想定外の権限が入っていないこと |
| 4-6 | ログ監査 | リリースビルドで通知本文がログに出ないことを確認 |
| 4-7 | 文言監査 | 「自動で解約」を示唆する表現が3言語のどこにもないことを確認 |
| 4-8 | プライバシーポリシー | 3言語で公開し、URL を取得 |
| 4-9 | データ安全性フォーム | 実装と一致する内容で回答 |
| 4-10 | 通知アクセスの申告 | Play Console のフォームを提出 |
| 4-11 | ストアリスティング | 3言語のアプリ名・説明・スクリーンショット |
| 4-12 | 内部テスト → 製品版 | クローズドテストを経て公開 |

### 4-4 が最も時間を食う

「数日放置後に通知が届くか」は**待つ以外に検証方法がない**。
Phase 4 の初日に仕掛けて、他のタスクと並行して結果を待つ。

実機が手元にない場合、クラウド端末ファーム（Firebase Test Lab 等）では
数日放置のシナリオを再現できない。**実機の確保を Phase 0 の時点で計画する。**

## リスク一覧

| リスク | 影響 | 対策 |
|---|---|---|
| **通知アクセスの審査落ち** | プロジェクトが成立しない | [policy-compliance.md](policy-compliance.md) の要件を Phase 1 から守る。申告と実装を一致させる |
| **通知フォーマットの変更** | 検知率の低下 | パターンをデータで配信し、アプリ更新なしで直せる構造にした |
| **OEM のプロセス強制終了** | 通知が届かない | 多段の再武装 + ユーザーへの設定案内。100% は約束しない |
| **解約URLの陳腐化** | 誤ったページに飛ばす | `last_checked` を持ち、6ヶ月で再検証。`verified: false` は公開しない |
| **コーパス収集の遅延** | Phase 1 が伸びる | Phase 0 から並行着手。クリティカルパスとして扱う |
| **実機の確保** | Phase 4 が検証できない | Phase 0 で調達計画を立てる |

## 意図的に初期リリースに含めないもの

- 繁体字中国語（`values-zh-rTW`）
- 広告
- クラウド同期・アカウント
- 支出の集計・グラフ
- 解約完了の記録と「守れた金額」の表示
- ウィジェット
- 鍵ローテーション

**「守れた金額の累計表示」は魅力的だが、Phase 2 以降に回す。**
まず「通知が確実に届く」を成立させることが優先。
